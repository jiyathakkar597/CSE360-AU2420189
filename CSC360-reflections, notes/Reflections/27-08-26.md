## Topics covered (revision checklist)

* Understand the purpose of **Maven** as a Java build automation and dependency management tool
* Understand the role of the **`pom.xml`** file and the purpose of `groupId`, `artifactId`, and `version`
* Understand **JAR files** as ZIP-based archives containing compiled Java classes, resources, and metadata
* Understand how Maven **repositories** store and retrieve JAR and POM files
* Understand the difference between the **local repository** and remote repositories
* Understand **dependencies** and how Maven manages them automatically
* Understand **transitive dependencies**, where Maven automatically fetches dependencies required by another dependency
* Understand the difference between Maven commands such as `compile`, `test`, `package`, `install`, and `deploy`
* Understand the difference between **installing** an artifact locally and **deploying** it to a remote repository
* Understand the basic purpose of **CI/CD** and how code changes are built, tested, and eventually deployed
* Understand **character encoding**, including ASCII, Unicode, and UTF-8
* Consider software beyond functionality by thinking about **time, memory, security, and maintainability**

## What we did in class

* Explored the structure of a Maven project and discussed how Maven uses `groupId`, `artifactId`, and `version` to identify and organize artifacts
* Examined **JAR files** and understood that they are essentially ZIP files containing Java classes and other project resources
* Discussed how Maven searches the **local repository first** and retrieves missing dependencies from a remote repository
* Explained how the `groupId` is converted into a folder structure inside the Maven repository
* Discussed the role of the **POM file** in storing project and dependency information
* Covered **transitive dependency management** and how Maven automatically fetches dependencies required by other libraries
* Discussed Maven's `install` and `deploy` commands and the difference between local and remote repositories
* Introduced **CI/CD**, using a simple example of developers pushing changes, followed by building and testing the updated project
* Discussed **character encoding** and why UTF-8 is commonly specified for Java source files
* Compared ASCII with Unicode/UTF-8 and discussed why different character encodings are needed to support different languages
* Discussed software development from a professional perspective, particularly the importance of considering **time, memory, security/risk, and maintainability**, rather than only checking whether the program works.
