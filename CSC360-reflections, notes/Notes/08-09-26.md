# GUI Components, Event Model & Image Processing

## 1. Event Model in GUI

* A GUI is continuously running and **waits for user actions/events**.
* Events can include mouse clicks, key presses, etc.
* An **event source** is the component where the event occurs.
* Events may propagate through a hierarchy of components.
* The source can handle the event or allow it to propagate further.

## 2. Layout Managers

* Layout managers control the **position and arrangement** of GUI components.
* When the window is resized, the layout manager reorganizes the components accordingly.
* Layout is important for creating adaptable interfaces.

## 3. Common GUI Components

### Checkbox

* Allows **multiple options** to be selected.

### Radio Button

* Used when the user should select **one option** from a group.

### Slider

* Used to select a **continuous value or range**.
* Useful when users want to adjust a value visually, such as volume.

### Dialog Box

* Used to **focus the user's attention** on an important interaction.
* A modal dialog requires the user to respond before continuing with the main interface.
* Its key UX benefit is maintaining the user's **context and focus** while requiring an important decision.

## 4. Exceptions

* Exceptions handle unexpected situations during program execution.
* **Checked exceptions** must be handled or declared.
* **Unchecked/runtime exceptions** do not have to be explicitly declared.
* Exceptions are important for writing reliable software.

## 5. Java Generics

* Generics allow algorithms and classes to work with different data types.
* Example:

```java
<T extends Comparable<T>>
```

* This allows the same algorithm to operate on different comparable types.

## 6. Collections and Views

* Collections are commonly used to store groups of objects.
* A **view** can provide access to data without necessarily allowing modification.
* Read and write access should be considered separately when designing data structures.

## 7. Graphics and Event Handling

* Graphical applications depend heavily on the **event-driven model**.
* Unlike a simple console program, a GUI remains active and responds to events as they occur.
