# SSH vs HTTPS

**SSH (Secure Shell)** and **HTTPS (HyperText Transfer Protocol Secure)** are both used for secure communication, but they are mainly used for different purposes.

- **SSH:** Used for **secure remote access** to computers and for securely interacting with services such as Git repositories.
- **HTTPS:** Used for **secure communication between a web browser and a web server**.

## SSH Key Pair

- SSH commonly uses a **key pair** consisting of a **public key and private key**.
- The keys can be **generated using a key-generation tool**.
- The **public key** can be shared, while the **private key** must be kept secret.
- This key pair can be used to authenticate with a server without entering a password each time.

### Key Point

- **SSH →** Secure remote access/authentication using a key pair.
- **HTTPS →** Secure communication over the web using TLS.

# Q. Describe the Graphical Frameworks in Java

Java provides several graphical frameworks for creating **GUI (Graphical User Interface)** applications:

### 1. AWT (Abstract Window Toolkit)

- The original Java GUI framework.
- Uses **native operating system components**.
- It is part of the standard Java platform.

### 2. Swing

- Built on top of AWT.
- Provides more advanced and flexible GUI components.
- It is part of the **Java Foundation Classes (JFC)**.

### 3. JavaFX

- A newer framework for creating modern and rich GUI applications.
- Provides features such as **CSS styling, animations, graphics, and multimedia**.
- In modern Java versions, JavaFX is generally **separate from the JDK**, so it needs to be added as an external dependency/module.

# Q. What is the Design Pattern for Creating User Interfaces?

The **Event Listener Model** is used in Java GUI programming to handle user interactions.

It consists of:

- **Event Source:** The component that generates the event, e.g., a button.
- **Event:** An action performed by the user, e.g., clicking a button.
- **Event Firing:** The event source generates/fires the event.
- **Event Listener:** Receives the event and performs the required action.

### Example

When a user clicks a button, the **button (event source)** fires a **click event**, which is handled by the registered **event listener**.

# Q. How is Static Graphics Different from Interactive Graphics?

**Static graphics** are graphics that are **drawn and remain unchanged** unless they are manually redrawn.

**Interactive graphics** respond to **user actions**, such as mouse movement, clicking, or keyboard input. When the user interacts with the graphic, the system detects the event and **repaints (redraws)** the graphics to show the required change.

### Example

A static graph only displays the data, while an interactive graph may show a **tooltip when the mouse is moved over a bar**.

**Therefore, graphics only display information, whereas interactive graphics respond to user events through event handling and repainting.**

# Q. Describe SSH and HTTPS Protocols for Accessing a Git Repository

- **SSH:** Used to securely connect to and interact with a Git repository using **SSH authentication**. It commonly uses a **public and private key pair**, allowing authentication without entering a password each time.
- **HTTPS:** Used to access and interact with a Git repository through the **HTTPS protocol**. Authentication is generally handled using credentials or a **Personal Access Token (PAT)**.

### Key Difference

- **SSH →** Key-based authentication.
- **HTTPS →** Web-based secure connection using TLS and credentials/token authentication.

# Q. What are Public Keys and Private Keys and How Do You Use Them?

A **public key and private key** form a cryptographic key pair.

- **Public Key:**
  - Can be shared with others.
  - Stored on the server or Git hosting service.
  - Used to identify or authenticate the user.

- **Private Key:**
  - Must be kept secret.
  - Stored securely on the user's computer.
  - Used to prove ownership of the corresponding public key.

### How They Are Used

1. Generate a public-private key pair.
2. Add the **public key** to the server or GitHub account.
3. Keep the **private key** securely on your computer.
4. When connecting, the server verifies that you possess the corresponding private key.
5. If the verification succeeds, access is granted.

# Digital Image

A **digital image** is a **2D matrix** in which each cell represents a pixel. Each pixel contains a value, which can be a single number, grayscale value, or an RGB color code.

To create an image, we need **one value for every row and column**.

### Example

Imagine a classroom where each cell represents a student. Assign each student a score from 1 to 10 and use that score to represent brightness:

- **1 → Dark**
- **10 → Bright**

Similarly, in a digital image, the value stored in each cell determines the appearance of that pixel.

# Chapter 2: Basic Principles of 2D Graphics

## Raster vs Vector Graphics

### Raster Graphics

- Raster graphics are made up of a **2D matrix (grid) of pixels**.
- Each pixel stores a **color value**.
- Image quality depends on the **resolution** (number of pixels).
- When enlarged, the pixels become visible, causing the image to look **blurry or pixelated**.
- Higher resolution generally means **more pixels and a larger file size**.

### Vector Graphics

- Vector graphics are **not made of pixels**.
- They use **drawing logic and mathematical descriptions** of shapes such as lines, curves, and polygons.
- The computer stores information about **how to draw the object** and redraws it **at runtime** according to the given dimensions.
- They can be **scaled to any size without losing quality or resolution**.
- Examples include **Adobe Illustrator files and vector-based PDFs**.

### Key Difference

| Raster Graphics | Vector Graphics |
|---|---|
| Made of pixels | Made using drawing logic |
| Resolution-dependent | Resolution-independent |
| Can pixelate when enlarged | Does not lose quality when enlarged |
| Stores pixel/color information | Stores mathematical descriptions of shapes |

**In short:**

> **Raster → Pixels → Resolution-dependent → Pixelates when enlarged.**

> **Vector → Drawing logic → Resolution-independent → No loss of quality when enlarged.**

# Windows vs Linux

## 1. Font Rendering

- **Windows** provides better **font rendering** (e.g., **TrueType Fonts**), making text appear **clearer and easier to read**.
- **Linux** generally has less refined font rendering, so text may not look as smooth or sharp.
- This difference is especially noticeable while **reading code or long text**.

## 2. Driver Compatibility

- **Windows** has excellent **driver support**.
  - Most hardware devices such as printers, Wi-Fi adapters, and graphics cards work immediately after installation.
- **Linux** may require **manual installation or configuration of drivers** for some devices.
- Although it may take extra effort, setting up drivers in Linux is **possible**.

## Comparison Table

| Windows | Linux |
|---|---|
| Better font rendering (TrueType fonts) | Font rendering may be less polished |
| Clearer and smoother text display | Text may appear less smooth |
| Better hardware driver support | Some drivers may require manual installation |
| Most devices work out of the box | May need additional configuration |

# Q. Advantages of Windows over Linux?

Windows has some advantages over Linux, especially in terms of **user experience and compatibility**:

- **Better font rendering:** Text appears clearer and more readable on the screen.
- **Better coding experience:** Code and text can be easier to read due to clearer visual display.
- **Better visual display:** Fonts and other UI elements are generally more polished for everyday use.
- **Better hardware compatibility:** Most hardware devices have drivers that work easily with Windows.
- **Ease of use:** Many devices and applications work out of the box with minimal configuration.
