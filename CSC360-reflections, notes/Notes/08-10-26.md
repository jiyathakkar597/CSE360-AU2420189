# **Encapsulation, JavaFX Layouts, Git Hooks, Visual Design, and Project Evaluation**

## 1. Encapsulation, Naming and Code Structure

- **Meaningful naming:** Public methods, classes, and properties should have names that make their purpose understandable.
- **Encapsulation:** Internal implementation details should be hidden behind a clear public interface.
- **Code organization:** Follow standard project structures so that production code and test code remain separate.

In Java projects, production code typically belongs in `src/main`, while tests belong in `src/test`.

## 2. JavaFX Layouts and Responsive Design

The lecture discussed JavaFX layouts and how components are arranged within a window.

- **VBox:** Arranges components vertically, one below another.
- **StackPane:** Places components on top of one another, allowing overlapping content.
- **Relative sizing:** Percentage-based dimensions depend on the parent container's size.
- **Responsive layouts:** Components should adjust when the window is resized rather than relying entirely on fixed dimensions.

Understanding the parent-child relationship between layout containers is important when designing flexible interfaces.

## 3. JavaFX Application Structure

A JavaFX application should separate its interface from its underlying logic.

- **FXML:** Defines the user interface layout.
- **Controllers:** Handle user interactions and coordinate application behaviour.
- **Background tasks:** Can perform longer operations without unnecessarily blocking the user interface.
- **Splash screens:** Display an introductory or loading screen while the application prepares to launch.

The lecture also questioned unnecessary startup operations, emphasizing that users should not have to wait for work that could be handled more efficiently.

## 4. Git Hooks and AI-Assisted Coding

The lecture discussed Git commit messages and attribution when using AI coding assistants.

- AI coding tools may add `Co-authored-by` information to commit messages.
- Commit messages should be reviewed before committing code.
- **Git hooks** can automatically check commit messages and reject those that violate specified rules.
- A `pre-commit` or, more specifically for commit-message validation, a `commit-msg` hook can enforce these checks.

The broader lesson is to understand the tools used in development and maintain control over project contributions and commit history.

## 5. Visual Design and Accessibility

The lecture emphasized that effective visualization and presentation are important parts of software development.

- **Show, don't just tell:** Use screenshots, diagrams, and demonstrations instead of text-heavy slides.
- **One idea per slide:** Keep each slide focused and easy to understand.
- **Reduce clutter:** Highlight important information instead of overwhelming the audience.
- **Colour accessibility:** Do not rely on colour alone to communicate differences; use shapes, patterns, or labels as additional indicators.
- **Visual hierarchy:** Present the most important information first.

A useful interface should communicate information clearly while minimizing the effort required from the user.

## 6. Project Evaluation and Presentation

The instructor reviewed student projects and highlighted the importance of presenting the actual product rather than simply describing its features.

A strong project presentation should:
- Demonstrate the working application early.
- Explain the main problem and the solution.
- Use screenshots or live demonstrations where appropriate.
- Explain important implementation decisions.
- Avoid unnecessary technical descriptions that do not help the audience understand the product.

The discussion also emphasized understanding the code, APIs, and design choices behind a project.
