## 1. Mathematical Definitions: Sets and Graphs

- **Set:** A well-defined collection of distinct elements, e.g., \(A=\{1,2,3,4\}\).
- **Graph:** Represented as \(G=(V,E)\), where \(V\) is the set of vertices and \(E\) is the set of edges.
- **Undirected graph:** Edges have no specified direction.
- **Directed graph:** Edges have a specified direction.
- The lecture also briefly discussed dependence and independence in mathematical problem-solving.

## 2. JavaFX Event Handling

Event handling allows applications to respond to user actions, such as mouse clicks and button presses.

```java
node.setOnMouseClicked(event -> {
    System.out.println("Mouse clicked");
});
```

`setOnMouseClicked()` registers a handler that executes when the node is clicked.

When tracing an interaction, identify the event handler, the logic it executes, and the objects or properties it modifies.

## 4. Java Records vs. Regular Classes

**Records** provide a concise way to represent data.

```java
public record Point(double x, double y) {}
```

Java automatically generates a constructor, accessors, and methods such as `equals()`, `hashCode()`, and `toString()`.

**Regular classes** require more code for equivalent functionality but offer greater implementation flexibility.

## 5. Tree Visualization and Layout

The project discussed in class involved drawing a tree on a canvas. The main challenge is converting the tree's structure into appropriate screen coordinates.

Node positioning may depend on:
- Number of nodes and tree height.
- Number of nodes at each level.
- Canvas dimensions and spacing.

Hard-coded coordinates may fail when the tree or canvas size changes.

### Separating Responsibilities
- **Tree structure:** Stores nodes and their relationships.
- **Layout logic:** Calculates node positions.
- **Drawing logic:** Renders nodes and connecting edges.

Keeping these responsibilities separate where appropriate can improve maintainability and reduce unnecessary duplication.

## 6. Software Design and Maintainability

When deciding where information belongs, consider:
- What information does each object represent?
- Can the information be calculated when needed?
- Could storing it in multiple places cause inconsistencies?
- Will the design accommodate future changes?

Clear responsibilities make code easier to understand and maintain.
