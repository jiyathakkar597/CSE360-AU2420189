## 1. Geometric Distribution

The geometric distribution models the **number of independent trials required to obtain the first success**, when each trial has the same probability of success.

Let:
- \(p\) = probability of success in each trial.
- \(X\) = number of trials required to obtain the first success.

The probability mass function is:

P(X = k) = (1 − p)ᵏ⁻¹ × p, where k = 1, 2, 3, …

The first \(k-1\) trials must fail, followed by a success on trial \(k\).

### Mean and Variance

\[
E[X]=\frac{1}{p}
\]

\[
\operatorname{Var}(X)=\frac{1-p}{p^2}
\]

**Example:** If the probability of success is \(0.2\), the expected number of trials until the first success is:

\[
E[X]=\frac{1}{0.2}=5
\]

This does not guarantee success on the fifth trial; it represents the long-run average number of trials required.

### Connection to the Binomial Distribution

- **Binomial distribution:** Counts the number of successes in a fixed number of trials.
- **Geometric distribution:** Counts the number of trials needed to obtain the first success.

The geometric distribution assumes independent trials with a constant, non-zero probability of success.


## 2. Code Documentation and Readability

The lecture discussed how documentation helps other developers understand a project without having to understand every implementation detail.

### Documentation Priorities

Good documentation should:
- Explain what a class or method does.
- Use meaningful class, method, and variable names.
- Provide brief descriptions that help readers understand the purpose of the code.
- Use comments when additional clarification is necessary.

Documentation should be useful rather than unnecessarily lengthy. Meaningful names and a clear structure can often explain code more effectively than excessive comments.

### JavaDoc

JavaDoc generates HTML documentation from specially formatted comments in Java source code.

For example:

```java
/**
 * Calculates the total of two numbers.
 *
 * @param a the first number
 * @param b the second number
 * @return the sum of the two numbers
 */
public int add(int a, int b) {
    return a + b;
}
```

Tags such as `@param` and `@return` describe method parameters and return values.

JavaDoc can also generate hyperlinks to referenced classes and methods. These links allow readers to navigate the documentation; they do not automatically provide additional explanations beyond the information available in the source and generated documentation.


## 3. Java Project Structure

A well-organized project separates production code, test code, and supporting resources.

A typical Java project structure is:

```text
project/
├── src/
│   ├── main/
│   │   ├── java/
│   │   └── resources/
│   └── test/
│       ├── java/
│       └── resources/
├── pom.xml
└── README.md
```

### Main Components

- **`src/main/java`:** Contains the application's production Java code.
- **`src/main/resources`:** Contains resources required by the application.
- **`src/test/java`:** Contains test code.
- **`src/test/resources`:** Contains resources used during testing.
- **`pom.xml`:** Defines Maven project configuration and dependencies.
- **`README.md`:** Introduces the project and explains how to use or run it.

### Naming Resources

The lecture highlighted the importance of using appropriate folder names. Since `resources` has a specific conventional meaning in Java projects, unrelated files such as demonstration media may be better placed in a clearly named folder such as `media` or `demo`.

A standard project structure makes code easier to navigate, maintain, test, and understand.


## 4. Private Constructors and Application Design

A private constructor prevents other classes from directly creating instances of a class using that constructor.

For example:

```java
public class Application {

    private Application() {
        // Prevent external instantiation
    }

    public static void main(String[] args) {
        System.out.println("Application started");
    }
}
```

Here, the constructor is private, so another class cannot create an `Application` object using `new Application()`.

### Why Use a Private Constructor?

The lecture discussed why an application class may not need to be instantiated by external code.

A private constructor can:
- Prevent unnecessary object creation.
- Restrict how a class is used.
- Make the intended design clearer.
- Avoid exposing functionality that other classes do not need.

However, private constructors are not necessary for every class. They should be used when the design requires restricted instantiation, rather than applied automatically.


## 5. Unit Testing and Meaningful Test Cases

Testing should verify that code behaves correctly, not merely that it compiles or that an object can be created.

### What Makes a Test Useful?

A meaningful test should:
- Exercise the behaviour being tested.
- Check the expected output or result.
- Detect incorrect behaviour when possible.
- Include relevant edge cases and failure scenarios.

For example, simply checking that an object is not `null` may not establish that its methods work correctly.

```java
@Test
void additionReturnsCorrectResult() {
    assertEquals(5, add(2, 3));
}
```

This test checks a specific expected result rather than merely confirming that the code can execute.

### Testing Application Logic

The lecture also discussed testing logic separately from graphical interfaces. For applications involving visual elements, testing the underlying logic can be simpler than automating every interaction with the interface.

For example, an image-processing method can be tested by checking how it transforms pixel values, without necessarily testing the entire graphical application.

**Key takeaway:** Tests should provide meaningful evidence of correctness rather than a false sense of confidence.

## 7. Pixels and Image Processing

A digital image consists of pixels arranged in rows and columns. Each pixel stores information about its colour.

For an 8-bit RGB colour channel, values range from:

\[
0 \leq R,G,B \leq 255
\]

- `0` represents the minimum intensity of a channel.
- `255` represents the maximum intensity of a channel.

The combination of red, green, and blue values determines the colour of a pixel.

### Pixel Processing

Pixel processing involves reading and modifying pixel values to transform an image.

A simple example discussed in the lecture was **colour inversion**.

For an 8-bit RGB image, the inverted values are:

\[
R'=255-R
\]

\[
G'=255-G
\]

\[
B'=255-B
\]

For example, a black pixel with RGB values \((0,0,0)\) becomes white:

\[
(255-0,255-0,255-0)=(255,255,255)
\]

Similarly, a white pixel with values \((255,255,255)\) becomes black.

Applying this operation to every pixel produces an inverted image.

### Image Processing Workflow

A basic image-processing workflow is:

1. Load the image.
2. Access its pixel data.
3. Apply a transformation to the pixels.
4. Generate or display the resulting image.

An image histogram represents the distribution of pixel intensities in an image.

For a grayscale image, a histogram typically shows:
- **Horizontal axis:** Pixel intensity values.

Histograms help analyse the brightness and intensity distribution of an image. They can also support image-enhancement and contrast-adjustment techniques.
