# Maven, JAR, Dependencies, CI/CD & Character Encoding

## 1. Maven

**Maven** is a Java build and dependency management tool. It helps with:

* Compiling code
* Running tests
* Packaging projects
* Managing dependencies
* Installing and deploying artifacts

Maven uses a **`pom.xml`** file to define project information and dependencies.

### Important POM Elements

```xml
<groupId>org.example</groupId>
<artifactId>my-project</artifactId>
<version>1.0</version>
```

* **Group ID:** Identifies the organization or project group.
* **Artifact ID:** Identifies the project or library.
* **Version:** Specifies the version of the artifact.

---

## 2. JAR Files

**JAR (Java ARchive)** is essentially a ZIP file containing Java files.

It can contain:

* `.class` files
* Resources
* Metadata

Example:

```text
META-INF/
com/
    example/
        MyClass.class
```

Java packages are represented as folders inside the JAR.

---

## 3. Maven Repository

A **Maven repository** stores JARs, POM files, and different versions of libraries.

### Local Repository

Usually located at:

```text
~/.m2/repository
```

Maven first checks the local repository. If the dependency is not available, it retrieves it from a remote repository and stores it locally.

The folder structure is based on:

```text
groupId → artifactId → version
```

For example:

```text
org/
└── example/
    └── my-project/
        └── 1.0/
```

---

## 4. Dependencies

A **dependency** is a library required by a project.

Maven automatically downloads dependencies declared in `pom.xml`.

### Transitive Dependencies

If:

```text
Project → Library A → Library B → Library C
```

Maven can automatically fetch B and C when A is required.

This avoids manually downloading and managing many JAR files.

---

## 5. Maven Commands

| Command       | Purpose                                     |
| ------------- | ------------------------------------------- |
| `mvn compile` | Compile the source code                     |
| `mvn test`    | Run tests                                   |
| `mvn package` | Create a JAR/package                        |
| `mvn install` | Store the artifact in the local repository  |
| `mvn deploy`  | Publish the artifact to a remote repository |

### Install vs Deploy

**Install:** Stores the artifact in the local repository.

**Deploy:** Publishes the artifact to a remote repository so other developers/projects can access it.

---

## 6. CI/CD

### CI — Continuous Integration

**Continuous Integration** means frequently integrating code changes from developers and automatically building and testing the combined code.

Example:

```text
Code Changes
     ↓
Build
     ↓
Test
     ↓
Success / Failure
```

The goal is to detect integration problems early.

### CD — Continuous Delivery/Deployment

CD moves successfully built and tested software toward release or deployment.

```text
Build → Test → Package → Deploy
```

### Integration vs Deployment

* **Integration:** Combining code changes and checking whether the project still works.
* **Deployment:** Making the application or artifact available in its target environment.

---

## 7. Character Encoding

Computers represent characters using numbers.

A **character encoding** defines the mapping between characters and numerical values.

```text
Character ↔ Numerical Representation
```

### ASCII

**ASCII (American Standard Code for Information Interchange)** supports a limited set of characters, mainly:

* English letters
* Numbers
* Punctuation
* Control characters

### UTF-8

**UTF-8** is a widely used Unicode encoding that supports characters from many languages.

Maven projects commonly specify the source encoding as:

```text
UTF-8
```

This helps prevent problems when source code contains characters that are not interpreted correctly.

---

## 8. Why Different Character Encodings Exist

ASCII was designed mainly for English and has a limited range of characters.

Different languages require many more characters, such as:

* Hindi
* Chinese
* Japanese
* Arabic
* Korean

Unicode and UTF-8 provide support for a much wider range of characters.

## 9. Software Development Perspective

A good programmer should think beyond:

> "Does it work?"

Important considerations include:

* **Time:** How quickly does it run?
* **Memory:** How much memory does it use?
* **Security/Risk:** Is it safe and reliable?
* **Correctness:** Does it produce the expected result?
* **Maintainability:** Can the code be easily changed or maintained?

The goal is not just to make software work, but to make it **efficient, reliable, and maintainable**.

---

## 10. Overall Maven Workflow

```text
Write Code
    ↓
Configure pom.xml
    ↓
Declare Dependencies
    ↓
Maven Resolves Dependencies
    ↓
Compile
    ↓
Test
    ↓
Package
    ↓
Create JAR
    ↓
Install / Deploy
```

## Key Takeaways

* **Maven** automates Java builds and dependency management.
* **`pom.xml`** contains project and dependency information.
* A **JAR** is essentially a ZIP archive containing Java classes and resources.
* **Group ID, Artifact ID, and Version** identify a Maven artifact.
* Maven uses repositories to store and retrieve dependencies.
* **Transitive dependencies** are dependencies required by other dependencies.
* `mvn install` stores an artifact locally.
* `mvn deploy` publishes an artifact to a remote repository.
* **CI** integrates, builds, and tests code changes automatically.
* **CD** moves tested software toward delivery or deployment.
* **Character encoding** maps characters to numerical representations.
* **UTF-8** supports a wide range of characters and is commonly used in modern software.
* Good programmers consider **time, memory, security, correctness, and maintainability**.
