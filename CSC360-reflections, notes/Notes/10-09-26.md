# Streaming, Statistics, XML/SVG & Networking

## The core idea: what is streaming?

**Streaming** means processing data as it arrives instead of waiting for the entire dataset to be available first.

This becomes especially useful when the data is:

* Very large
* Continuously generated
* Too large to comfortably keep in memory

**Basic idea:**

`Receive data → Process it → Keep only what is needed → Continue`

The main advantage is **memory efficiency** because we do not need to store the complete dataset.

## Streaming vs downloading

The important difference is how the data is consumed:

* **Downloading:** generally obtain the complete file/data before using it.
* **Streaming:** start processing/using the data while it is still arriving.

For example, video can be streamed in smaller portions rather than loading the entire video into memory before playback starts.

## Computing statistics while streaming

A useful application of streaming is calculating statistics without storing every value.

For the **mean**:

$$
\mu = \frac{\sum x}{n}
$$

While processing the data, we only need to maintain:

* Running sum
* Number of values received

So even if there are millions of values, we do not necessarily need to store all of them.

### Variance

Variance can be represented as:

$$
\sigma^2 = E[X^2] - (E[X])^2
$$

This means that while streaming, we can maintain information such as:

* Number of observations
* Running sum of values
* Running sum of squared values

This allows the calculation to be performed using a small amount of stored information.

## Population mean vs sample mean

There are two related but different situations:

**Population mean:**

$$
\mu = \frac{\sum X}{N}
$$

**Sample mean:**

$$
\bar{x} = \frac{\sum x}{n}
$$

The main difference is whether we are working with the **entire population** or only a **sample** taken from it.

## XML and SVG

**XML** is a text-based format that can represent structured information.

**SVG (Scalable Vector Graphics)** uses an XML-based representation for graphical objects.

Instead of storing only the final pixels, graphical information can be represented using things such as:

* Shape
* Position
* Size
* Other properties

This makes it possible to **save and reconstruct graphical objects later**.

## Why persistence matters

Suppose a user creates a diagram and closes the application.

If the application does not save the graphical information, the work is lost.

Therefore, a graphical application needs **persistence** — the ability to store the state of the application so that it can be restored later.

For a graphical object, this could include:

* Its type
* Position
* Size
* Properties
* Relationships with other objects

## Graphics and networking

Graphics applications can also communicate across computers using **networking**.

For example, a graphical application can:

* Request data from another computer
* Send graphical information
* Display information received from a server
* Allow a user to interact with a remote system

### Client vs Server

**Client:** requests services/data and usually interacts directly with the user.

**Server:** provides data or performs services requested by clients.

A graphical application can therefore involve both **local rendering/interaction** and **network communication**.

## Why these concepts connect

These topics are connected to building larger graphical applications:

**Streaming** → handle large/continuous data efficiently

**Statistics** → process data without storing everything

**XML/SVG** → represent and save graphical information

**Persistence** → restore work after closing the application

**Networking** → exchange data between different systems

The overall idea is that a graphics application is not only about drawing objects — it also needs to manage **data, storage, processing, and communication**.
